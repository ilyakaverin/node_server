# kazna_watcher

Следит за разделами сайта Федерального казначейства (roskazna.gov.ru) и присылает
письмо, когда в разделе появляются новые файлы.

## Как работает

- Сразу при старте и затем каждые 5 минут загружает страницы разделов из
  `configuration/resources.json` и по CSS-селекторам находит заголовок, дату и
  ссылки на файлы.
- Если на странице есть ссылка, которой нет в базе (`database.json`), отправляет
  письмо каждому адресату из `MAIL_TO` и запоминает текущие ссылки.
- Первая обработка раздела (в том числе только что добавленного в конфигурацию)
  лишь запоминает текущие файлы — письма о том, что уже было на странице, не уходят.
- Одновременно выполняется только один запуск: если предыдущий ещё идёт
  (например, медленно отвечает SMTP), очередной пропускается.
- Повреждённая база не затирается: файл переносится в
  `database.json.corrupt-<время>`, и работа продолжается с пустой базой
  (то есть все разделы обрабатываются как первый раз, без писем).

## Установка и запуск

Нужен Node.js 20.18.1 или новее.

```sh
npm ci
npm start
```

Перед первым запуском создайте `.env` в корне проекта (см. «Настройка»).

По `SIGTERM`/`SIGINT` процесс перестаёт запускать новые проверки, дожидается
окончания текущей и завершается. Повторный сигнал завершает процесс сразу.

Сообщения в логе начинаются с метки времени в UTC (ISO 8601).

## Настройка

Переменные окружения читаются из `.env` в корне проекта:

| Переменная    | Назначение                                                    |
| ------------- | ------------------------------------------------------------- |
| `SMTP_HOST`   | SMTP-сервер                                                   |
| `SMTP_PORT`   | порт (по умолчанию 587)                                       |
| `SMTP_SECURE` | `true` — TLS сразу (обычно порт 465), иначе STARTTLS          |
| `SMTP_USER`   | логин SMTP                                                    |
| `SMTP_PASS`   | пароль SMTP                                                   |
| `MAIL_FROM`   | отправитель (по умолчанию `SMTP_USER`)                        |
| `MAIL_TO`     | получатели через запятую                                      |
| `DB_PATH`     | путь к базе (по умолчанию `database.json`)                    |
| `CONFIG_PATH` | путь к списку разделов (по умолчанию `configuration/resources.json`) |

Относительные пути считаются от корня проекта, а не от каталога, из которого
запущен процесс.

## Разделы

`configuration/resources.json` перечитывается при каждом запуске, перезапуск после
правки не нужен:

```json
{
  "resources": [
    {
      "id": "bank_deposits",
      "description": "Название раздела для письма",
      "url": "https://roskazna.gov.ru/...",
      "selectors": {
        "title": "CSS-селектор заголовка",
        "files": "CSS-селектор ссылок на файлы",
        "date": "CSS-селектор даты (необязательно)"
      }
    }
  ]
}
```

`id` должен быть уникальным: по нему в базе хранится история раздела.

## Сертификаты

Сайты госорганов используют сертификаты НУЦ Минцифры, которых нет в стандартном
хранилище Node.js. Парсер проверяет сертификаты сайтов и доверяет стандартным
корневым сертификатам, а также всем файлам `*.pem` и `*.crt` из каталога `certs/`.
Там лежат корневой и промежуточный сертификаты Минцифры. Откуда они взяты, их
отпечатки и порядок обновления описаны в [certs/README.md](certs/README.md).

Тесты не ходят в интернет: страницы разделов и SMTP заменены локальными
серверами и заглушками. В GitHub Actions тесты запускаются на Node.js 20, 22 и 24.
